- Mitigation present: separate reachability tests (`scripted_run_alone_produces_every_guarded_shape`, `the_fixed_proof_twin_alone_reaches_every_guarded_shape`) prove the script reaches shapes. They do not prove the random generator does.

### L1 (low, verified): launch value rule redacts legitimate mixed-case hyphenated model ids >= 32 bytes
- memory-core/src/privacy/launch.rs `opaque()` (second clause `upper && lower && digit`, no `plain` requirement) applied to segments split only on `/ : @ + .` (hyphen and underscore do not split). Input `--model meta-llama/Llama-4-Maverick-17B-128E-Instruct-FP8` : segment `Llama-4-Maverick-17B-128E-Instruct-FP8` is 38 bytes with upper+lower+digit -> `[redacted]`. A12.1 point 4 says that is the rule, but its "known limits" sentence only admits hyphenated lowercase-and-digit runs pass; mixed-case ones fail. Fail-closed (loses metadata, no leak). Also `(?i:0|1|true|false)` is Unicode-aware: `falſe` (U+017F) matches the Switch shape; harmless (5 chars) but "any case" was meant ASCII.
- Inputs that are secrets but pass (beyond A12.1 limits): none found. Checked: prefix match is on ASCII-folded value so `GHP_`, `Sk-` caught; `eyj` caught; AIza/AKIA/ASIA need exact case (spec says so). A lowercase-hex or lowercase-alnum secret of >=32 chars that contains `-` or `_` passes (UUID-shaped keys); inherent to the documented hyphen carve-out; same for session slot UUIDs which must pass. `names::matches` gates the ASCII shape first, so no non-ASCII reaches `to_ascii_lowercase`/zip; no byte slicing anywhere (zip of two splits, equal segment counts because lowercasing is length-preserving).

### L2 (low, latent, verified): `translate_with` uses `Path::is_dir`, which follows symlinks
- rust/crates/memory/src/watch.rs `appears && is_dir(&path)`: a symlink to a directory created or renamed into a root becomes `Input::DirCreated` -> `Action::ReadDir{path}`. DESIGN 8.2 / 7.1 say symlinks are never followed (realfs::walk skips them). `Action::ReadDir` is not wired yet (grep: no consumer outside watch.rs), so no current effect. Use `symlink_metadata().is_dir()` in the production closure, or make the consumer use walk (which does not follow). Also a blocking stat inside the notify callback thread per create/rename event.

### L3 (low, verified): oracle looser by one than production in capture_property
- capture_property.rs `read_chain`: `ensure(raw.len() <= 64)` checked before the push, so a 65-manifest chain is parsed; production recover_base now rejects at 64 (A12.3, commit.rs `>=`). `fold()` rejects >64 (`TooManySteps`) so a 65-chain still fails later; no hole, only a different error. 

### L4 (low, verified): `detectable()` avoidance is slightly wider than A12.2 documents
- capture_property.rs `detectable(index, len)` uses the CURRENT file length. When the file has grown since the last commit by G bytes, the model also relocates rewrites in [ct, ct+G) (ct = committed tail start) that the window check WOULD catch; they move to the current tail start, which is still inside the committed tail window if G < 65536, so a tail-window rewrite is still exercised. Net: no real hole found, but the avoided region is "gap of the current file", not "gap of the committed boundary". The daemon model (daemon.rs `masked`) is the opposite: permanent per-position exemption (never cleared), so a later genuine stale byte at a masked position that has since entered a window would be tolerated. Pre-existing; low.

### Info: daemon.rs status counters
- `launch_attach_failed` is counted per attempt (note_attach before the commit), so a commit that fails and is retried counts again. Counters persist only on the status cadence. Index/status damaged counters re-count on each restart until the replacement file is written. All acceptable as "events", not correctness.
- A newer-schema status.json is overwritten by this build (A12 open question at amendments:294); not a regression.
