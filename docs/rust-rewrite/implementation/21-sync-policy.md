# 21. Sync policy for durable state writes (amendment A7)

Status: implemented in the working tree, not committed. Evidence dated 2026-11-09.

## Changes
- `rust/crates/memory/src/state.rs`
  - `pub enum SyncPolicy { Full (default), None }`. `None` skips only the file `sync_all` and the directory fsync; temp file, write, rename and directory open are unchanged.
  - `StateDir` carries the policy. `StateDir::prepare` yields `Full`; `prepare_with(lock, SyncPolicy)` selects one. New `StateDir::sync_policy()` and `StateDir::stage(file, body)`.
  - One write path: `stage`/`write_durable` (free functions, always `Full`) and `StateDir::{stage, write, create_machine_id}` all go through `stage_with`; `Staged` carries the policy into `publish`/`publish_new`.
- `rust/crates/memory/src/daemon.rs`: `StartOptions { sync }` (`Default` = `Full`), `Daemon::start_with(root, cfg, parts, options)`. `Daemon::start` and `main_entry` use `Full`.
- `tests/daemon.rs`: `boot_sync`/`cycle_sync` take a policy; only `Sut` (the Hegel and proptest simulation properties) passes `None`. Example tests use `boot` (`Full`).
- `tests/state.rs`: `sync_policy_default_is_full`, and the crash-point property in a Hegel and a proptest form. All other tests keep `Full`.

## Crash-point property
`crash_point(old, new, point, junk, none)` writes `old`, then simulates a crash: 0 nothing staged; 1 `stage` then drop; 2 `stage`, drop, plus a torn temp file of generated bytes; 3 `stage` and `publish`. It then reloads with a fresh lock and `prepare_with`. Oracle, independent of the implementation: the body must be a member of {old, new}; points 0 to 2 must read `old`, point 3 must read `new` (a table in the test); no `.tmp-` file may remain after the next start. Bodies, junk, point and policy (`Full`/`None`) are generated.
