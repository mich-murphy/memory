## 4. Concrete core resolutions before affected implementation is accepted

### R1 — blocking protected-byte domain / whole-document transform contradiction

`DESIGN.md:563-568` hashes raw local bytes **before** transform; object naming says raw piece hash (`:371-375`), manifests describe size/whole digest/offsets (`:424-435`), but audit explicitly compares transformed bytes (`:710-711,966-981`). Redaction can change lengths and bytes. A reader verifying decompressed bytes against a pre-transform hash necessarily fails; raw protected digests also publish a fingerprint of secret-bearing local input, contrary to the protected publication intent. This is not resolved by a capability wrapper.

**Safe interpretation to pin:** “raw” in remote piece/hash fields means **uncompressed publishable bytes after whole-document transform**, not unsafe on-disk bytes. Raw source identity/size/mtime/fingerprints remain local; protected snapshots publish transformed size, piece offsets and whole digest. Protect the entire JSON/TOML before slicing it: duplicate keys, escaped copies and all-identity union cannot be validated independently on arbitrary 8 MiB fragments. Use the Go bounded whole-doc fixture behavior (`internal/sessioncapture/derived.go:277-290`) as semantics, not its spool. Reject/withhold when bounded parsing cannot safely complete; never fall back to raw. Declare memory/size limits or a bounded transform strategy before claiming the S3 memory target. Scope/encoding/storage decisions remain unchanged.

**S1 acceptance fixture:** different raw configs yielding identical redacted bytes yield identical published digest domain; independent reassembly equals transform golden; no pre-transform digest appears remotely. Oversize/malformed/truncated protected documents return withholding, never partial output. SQLite backup and Codex decompression likewise need explicit source-vs-published byte domains.

### R2 — blocking encoded descriptor correctness after global dedup

`DESIGN.md:371-375` deliberately keeps raw keys stable across zstd upgrades; manifest records encoded_len and encoded_sha256 (`:430-432`); `:602` treats 412 as success; reader verifies encoded digest (`:909-910`). Two hosts/versions can compress identical publishable bytes differently. If writer B records its attempted encoded hash after 412, the stored object remains writer A's bytes; a correct reader rejects B's otherwise valid publication.

**Safe resolution:** preserve global uncompressed-content keys and immutable PUTs. On 412, reuse an already **verified actual stored representation descriptor**, or GET/verify stored bytes, decode/verify content hash and build the descriptor from the stored encoding. A local descriptor cache alone is not proof after rebuild. Do not overwrite, silently omit required checks or assume deterministic level-3 output across versions. S1 type/model fixture: two legal encodings of same bytes, one wins; every manifest descriptor matches the winner. S2 measures actual fetch/metadata mechanism; no client choice reopened.

### R3 — true false bound, not a reason to reopen checkpoint/retention decisions

`DESIGN.md:221` calls checkpoint cost “bounded by 64 pieces per checkpoint”; `:441-443` requires **all retained append epochs and all pieces**; one capture can itself add many pieces (`:559-560`). Thus checkpoint bytes are not bounded by 64 pieces. At most 64 **manifest GETs** from a current to checkpoint (`:456-457`) is consistent and remains valid. Delta/checkpoint amortization improves cost relative to rewriting every capture, but full checkpoints still grow with retained history; no proof of globally linear lifetime manifest upload bytes follows for arbitrarily long sessions (R6 `:90-93`). The one-transcript-source experiment is explicitly a limited model (`:211-214`), not multi-epoch evidence.

**Safe interpretation:** retain decided cadence 64 and append history/latest snapshot semantics. Remove the false bound from acceptance claims; report exact bytes for multi-source/multi-epoch synthetic histories, include serialization/memory/timeouts for large checkpoints, and distinguish one-window delta cost from lifetime checkpoint overhead. Do not change frozen experiments or claim a new measurement. Parent must reconcile literal proportional-manifest R6 with mandatory full checkpoints; core can implement the decided schema without pretending the cost contradiction is solved.

### R4 — locator needs explicit roots/ownership facts, not hidden I/O

`locate(path, roots)` is pure (`DESIGN.md:270-274,1009-1012`); external `file-history/<uuid>` lacks the project slug present in transcript owner (`internal/adapters/claude.go:109-112,122-125`). Go requires bounded owner lookup and returns pending/ambiguous (`internal/capturesource/ownership.go:54-75`). Counting UnknownOwner is fail-closed, but permanently counting it is not fulfilling R1. Root qualification is also absent from the illustrative SessionKey (`DESIGN.md:264-267`), while Go uses full root hash namespace (`classify.go:149-157`). Two custom roots may reuse session names.

**Safe resolution:** document validated immutable ownership/root-namespace facts supplied to core by the shell (or a pure lookup input); no filesystem access inside locator. Ambiguous duplicate UUIDs remain withheld/countable; no first-sibling heuristic. Define owner stable under unrelated siblings and route aliases, and define the missing artifact mappings from section 2. This resolves interfaces, not scope expansion.

### R5 — strict schemas vs narrow recovery parsing is reconcilable, but must be explicit

`DESIGN.md:471-476` requires deny_unknown_fields on every written type read, yet recovery reads only position fields; wire enums may be nonexhaustive only in reader copy (`:348-349`). A minimal recovery struct with deny_unknown_fields rejects all other valid manifest fields, and default serde enum parsing does not implement the newer-schema Park outcome automatically.

**Safe interpretation:** strict version-tag/envelope dispatch first; unsupported/newer remote schema → typed owner park, not generic parse retry. For supported schema, choose either full known manifest validation or an explicitly named projection decoder whose allowed field envelope includes the schema's other fields. Full semantic dependency/digest checks remain reader authority. Roundtrip alone is insufficient: duplicate fields, unknown fields/version/variants, op/class/epoch mismatches, integer overflow, path/key traversal, overlapping/gapped ranges, invalid digest lengths and bad predecessor/checkpoint/owner/sequence links require negative tests. Agent hook input remains tolerant key reads, while our persisted hints/config/state/manifests are strict. No retired schema compatibility is implied.

### R6 — capture oracle must distinguish observation assumptions from unconditional safety

`DESIGN.md:539-548` honestly accepts interior rewrite lag until audit; `:1092-1097` scopes property 1a and states audit convergence. Snapshot before/after fingerprint checks (`:580-582`) do not make a hostile mutable file atomic; Go likewise explicitly disclaims hostile path replacement (`internal/capturepolicy/resolve.go:16-18`; `docs/security.md:23-24`). Audit runs only when identity/size/mtime unchanged since capture (`DESIGN.md:968-970`): continuously appending sources may not qualify. “Any rewrite after one audit” must mean an eligible pinned-prefix audit, not a skipped timer tick. The broad R3 “no wrong byte” is already qualified by this stated model, not a reason to add a spool.

**S1 acceptance:** generator-owned immutable file versions and operation schedule, never planner-produced expected ranges; audit eligibility/skips explicit. Separate capture-visible rewrite safety from interior-rewrite eventual convergence. Include truncate-regrow, identity replacement, equal-size/racy writes, window endpoints, mid-UTF-8 and partial-line splits. A disabled window check must fail independent safety. Pending question for parent: whether active-source liveness needs a pinned-prefix audit that can run during append, or an explicit quiescence precondition; do not claim convergence after a skipped audit.

### R7 — nonblocking clarified semantics / remaining later-slice questions

- **Snapshot “latest only” is checkpoint selection**, not physical deletion of old immutable manifests/objects (`DESIGN.md:441-443,466`). Do not claim privacy revocation or disk-space reclamation from snapshot replacement; no GC added.
- **Rules digest** covers table, not all transform semantics (`internal/scrub/digest.go:12-16`). Pin an explicit transform semantic version/manual bump for parser/secret-name/reference/copy logic changes; otherwise table-only digest will not force replay (`DESIGN.md:708-709`). S1 golden guard must distinguish unchanged table from changed semantics.
- **Machine identity**: O_EXCL establishes a winner, not completed durable contents; use a crash-complete protocol satisfying F2/7a rather than silently rotating an empty existing file.
- **Launch durability**: state table says hints kept 7 days **and until launches committed** (`DESIGN.md:786`), so seven days is not an unconditional deletion deadline. Pending records must survive index loss. “Nothing lost” (`:882`) cannot literally cover hook ENOSPC/short-write fail-open (`:843-850`); preserve the known best-effort hook boundary, do not claim lossless launch capture under failed writes.
- **Loss-window counter** compares `captured_to` with last committed size (`DESIGN.md:941-944`), although SourceState defines captured_to as remembered position (`:297-300`) and index is updated after commit (`:617-618`). Shell must distinguish observed/read-but-uncommitted offsets to make the counter non-vacuous. Pin that later-slice state meaning; no speculative spill buffer.

## 6. Parent resolutions, irreconcilable criterion and minimal privacy interface

Parent accepted **transformed published-byte domain (R1)** and **verified actual stored encoding on dedup (R2)** as required safe interpretations during this audit. They are acceptance requirements, not requests to reopen the chosen layout. The missing-kind proposals above remain proposed, not independently accepted.

**Irreconcilable literal criterion, separately:** mandatory full retained-history checkpoints every 64 captures cannot simultaneously guarantee bounded 64-piece checkpoints or lifetime manifest bytes strictly proportional to appended content for arbitrarily long sessions (`DESIGN.md:90-93,221,441-443`). Keep decided checkpoints/retention; parent must explicitly qualify the cost claim and measure the appropriate slice. No new number or mechanism proposed. Other findings are resolvable interface/model preconditions rather than a reason to stop the decided rewrite.

**Minimal independently owned privacy-module interface (S1):**

- A pure `privacy` module owns opaque `RedactedBytes`, `AuthorizedBody`, closed `DenyReason`/`UnknownReason`, `TransformVersion` and the known-filename rule table. No I/O dependency. Shell owns resolution/open, supplies an immutable `ResolvedSourceFacts` containing all identity spellings plus file-identity evidence, located kind/owner, and policy/rules context. Facts are observations, not an upload capability.
- `admit(&PolicyContext, &ResolvedSourceFacts) -> Admission` returns `AdmittedSource | Deny | Unknown`; only module-private constructors mint `AdmittedSource`. It specifies required transform, never reads content. Resolution failure is an explicit input, never an empty permissive identity list.
- `transform(&AdmittedSource, bytes) -> Result<RedactedBytes, TransformFailure>` handles whole protected documents, all encountered schemas and applicable text guard; identity transform is allowed only for admitted nonprotected kinds. Published digest/length computed over returned bytes; raw fingerprints stay shell-local.
- `authorize(admitted, redacted, current_policy_context) -> Allow(AuthorizedBody) | Deny | Unknown` binds kind/owner/rules and exact transformed bytes. Compression is an internal provenance-preserving operation or a method consuming `AuthorizedBody`; never an externally forgeable unwrap/rewrap. Store-facing capability must survive this step.
- Separate `sanitize_launch(raw_args, raw_env) -> SanitizedLaunch` with private fields, consumed by strict hint/manifest builders; route/cwd fields use validated coordinate types. No arbitrary serialized metadata bypass. Privacy owner supplies golden synthetic vectors; an independently owned oracle supplies canary/safe-negative expectations, compile-fail capability tests and sink inspections.

This is a minimal ownership seam, not a demanded exact Rust signature. Locator/planner/coalescer/manifest builders can be implemented independently using these opaque outputs; policy module must not own filesystem resolution or remote clients.
